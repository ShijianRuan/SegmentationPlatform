# Mimics Research 21.0 可行性验证计划

> 版本：v0.6
> 更新日期：2026-06-13
> 状态：待在实际安装环境中执行

POC 是“可行性验证”的简称。这里不是验证 Mimics 能不能画 Mask，而是验证它能否以可控的操作成本接入平台。

能力探针是执行 POC 的必要代码，不需要等 POC 全部完成后才编写。生产工作流脚本则必须按 [Mimics 适配器设计与开发流程](mimics_adapter_design.md) 的 Gate A、B、C 分阶段进入。

最终要回答：

> Mimics 21.0 能否处理多病例和多序列，支持中断、复查与修订，并稳定产出空间位置正确、可由平台注册的新标签版本？

## 1. 开始前准备

### 1.1 记录环境

```yaml
mimics:
  product: Mimics Research
  version: 21.0
  edition: TO_FILL
  license_modules: TO_FILL
  executable: TO_FILL
  python: 3.5.2

external_runtime:
  python: TO_FILL
  numpy: TO_FILL
  nibabel: TO_FILL
  simpleitk: TO_FILL

machine:
  os: TO_FILL
  hostname_hash: TO_FILL
```

还要记录 Scripting Library、命令行运行脚本和 background mode 是否可用。不得使用 Mimics 2025 或 28 的功能代替 21.0 证据。

### 1.2 准备样例

准备 3 至 5 个已去标识病例：

| 样例 | 验证目的 |
|---|---|
| 单检查、单序列、规则 CT | 建立最简单基线 |
| 单检查、多序列 | 验证多个平等 image sets |
| 一个目录含多个检查或患者 | 验证自动分组 |
| 非等距 spacing 或复杂方向 | 验证空间坐标 |
| 带候选或草稿标签 | 验证初始 Mask 导入、编辑和导出 |

另准备一个人工体模。在已知索引位置放置不对称标记，使轴交换、翻转和 origin 偏移都能被看出来。

每个病例包至少包含：

- 患者、检查和序列清单；
- 每个 image set 的平台标识；
- 带 `target_id` 的标注目标；
- 去标识声明；
- 可选的基础标签及其哈希。

## 2. 验证总表

| 编号 | 验证内容 | 不通过的直接影响 |
|---|---|---|
| P01 | DICOM 分组 | 无法可靠建立病例和序列对应关系 |
| P02 | active image 与任务目标 | Mask 可能绑定错误序列 |
| P03 | 图像格式边界 | 无法确定输入准备方式 |
| P04 | 初始 Mask 注入 | 无法使用候选标签作为标注起点 |
| P05 | 空间坐标往返 | 标签可能静默错位，Mimics 不得进入主路径 |
| P06 | 选择性导出 Mask | 无法形成稳定提交 |
| P07 | `.mcs` 工作检查点 | 中断恢复成本过高 |
| P08 | 参数和批量运行 | 路径写死，无法规模化 |
| P09 | 对话框处理 | 标注负担过高或歧义被掩盖 |
| P10 | 保存、完成、复查和阻塞 | 平台无法表达真实标注过程 |
| P11 | 已验证标签的再次修订 | 版本链会被覆盖 |
| P12 | 多标注者 | 容易重复分配或相互覆盖 |
| P13 | 异常反馈 | 标注者不知道下一步该做什么 |
| P14 | 端到端闭环 | Mimics 仍只是孤立工具 |
| P15 | Project Tree 任务清单对象 | 不能用常驻、非阻塞清单替代反复弹窗 |

## 3. 具体实验

### P01 DICOM 分组

**目的**
确认一个输入目录中的患者、检查和序列如何成为 Mimics image sets。

**操作**

1. 使用底层 DICOM 检查和分组 API 记录预期结果。
2. 使用便捷导入入口导入同一目录。
3. 枚举实际 image sets，记录患者、Study、Series 和顺序。
4. 与平台预先生成的清单比较。

**证据**

- 输入清单；
- Mimics 分组日志；
- image set 与平台序列标识的映射表。

**通过条件**

- 不同患者不会被合并为一个病例；
- 每个预期序列映射到唯一 image set；
- 分组不一致时流程阻断并说明差异，不要求标注者猜选。

### P02 active image 与任务目标

**目的**
确认脚本可以在多序列项目中始终操作正确 image set。

**操作**

1. 导入至少两个需要标注的 image sets。
2. 按任务清单分别激活它们。
3. 在每个 image set 上创建带任务 metadata 的测试 Mask。
4. 保存并重开 `.mcs`，检查 Mask 与 image set 的绑定。
5. 手工切换界面显示后再次运行提交脚本。

**证据**

- 每个任务目标的 image set 标识；
- Mask 的 image 关联和 metadata；
- 重开前后的对照记录。

**通过条件**

- Mask 导入、编辑和导出都绑定任务声明的 image set；
- 用户最后点击哪个图像不会改变正式提交结果。

### P03 图像格式边界

**目的**
确认当前 Mimics 21.0 安装真正支持的图像输入。

**操作**

1. 测试 DICOM。
2. 测试 BMP、TIFF 和 JPEG。
3. 测试 raw，并记录必需参数。
4. 检查界面和 API 是否存在 NIfTI 或 MetaImage 入口。
5. 若存在文档未说明的入口，继续完成 P05。

**证据**

- edition 和 license；
- 使用的菜单或 API；
- 导入日志；
- 每种格式的空间验证结果。

**通过条件**

- 明确列出“支持、有限支持、不支持”；
- 不把“文件能打开”误写成“空间位置可靠”；
- 不使用新版文档替代当前安装证据。

### P04 初始 Mask 注入

**目的**
确认候选或草稿标签可以成为人工修正的起点。

**操作**

1. 先测试 Mimics 可用的直接标签导入。
2. 直接路径不能稳定保留空间和命名时，再测试数组交换。
3. 外部程序把标签对齐到目标 image set 网格。
4. 输出不使用 pickle 的 `bool` 或 `uint8` 数组，并记录哈希、shape、轴说明和 image set 标识。
5. Mimics 脚本逐器官创建 Mask、写入数组、设置名称和 metadata。
6. 使用人工体模和真实病例目视核对。

**证据**

- 输入标签及其哈希；
- 对齐和重采样记录；
- 交换清单；
- 注入后截图或检查报告。

**通过条件**

- 至少三个病例无需手工选择路径、重命名或配色；
- 每个 Mask 绑定正确 image set；
- 人工体模标记位于预期物理位置。

### P05 空间坐标往返

**目的**
证明数组索引、Mimics image set 和平台图像使用同一物理空间。

**操作**

1. 读取原点和三个单位轴索引的世界坐标。
2. 推导 Mimics 的索引到世界坐标变换。
3. 与原始平台图像的 affine、direction、origin 和 spacing 比较。
4. 注入人工体模 Mask，再读取导出数组。
5. 外部程序写回 NIfTI。
6. 在至少一个独立工具中叠加检查。

**证据**

- 四个坐标点；
- 推导出的变换；
- 输入与输出 header；
- 重采样方法；
- 独立工具叠加结果。

**通过条件**

- 轴顺序、轴方向、origin 和 spacing 都能解释；
- 不通过复制 header 伪造一致；
- 标签重采样只使用最近邻插值；
- 任一病例出现无法解释的翻转、轴交换或偏移时，主路径判定失败。

### P06 选择性导出 Mask

**目的**
确认可以按任务导出一个器官或一组器官。

**操作**

1. 传入任务标识、输出目录和器官名。
2. 只读取一个目标 Mask。
3. 再按提交清单导出一个完整目标组。
4. 由外部程序写出逐器官 NIfTI 和可选多标签文件。
5. 构造缺失、重复和未知 Mask。

**证据**

- 命令行参数；
- 导出清单；
- 输出哈希；
- 错误病例报告。

**通过条件**

- 路径和文件名不写死；
- 指定导出不会混入其他对象；
- 正式提交会拒绝缺失、重复和未知 Mask。

### P07 `.mcs` 工作检查点

**目的**
确认标注中断后可以继续，并明确跨机器边界。

**操作**

1. 导入多 image sets 和 Masks，编辑后保存当前格式 `.mcs`。
2. 关闭并重开，核对对象、绑定和进度。
3. 复制到第二台兼容机器测试。
4. 比较当前格式、旧版兼容格式和可选压缩。

**证据**

- 文件大小；
- 环境差异；
- 重开结果；
- 跨机器成功或失败原因。

**通过条件**

- 本机中断后可以继续；
- 跨机器限制被明确记录；
- 不依赖有损图像压缩；
- `.mcs` 损坏或不兼容时，病例包仍能重建工作区。

### P08 参数和批量运行

**目的**
确认一个脚本可由参数处理单个或多个病例。

**操作**

1. 通过 `-run_script` 传入任务清单和输出目录。
2. 用 `Labeling_Open_Next_Case.py` 连续打开多个任务。
3. 对无人工步骤使用 background mode。
4. 人为制造一个失败病例。

**证据**

- 实际命令；
- 每例退出码；
- 每例日志；
- 结果清单。

**通过条件**

- 输入和输出路径不在代码内写死；
- 单例和批量使用同一入口；
- 一个病例失败不会污染其他病例；
- 失败项可以单独重试。

### P09 对话框

**目的**
减少重复确认，同时不掩盖数据歧义。

**操作**

1. 记录正常导入中出现的所有内置对话框。
2. 只对预检查已确定答案的对话框设置预定义回答。
3. 构造方向、raw 参数或序列选择有歧义的输入。
4. 测试打开任务摘要、提交选择和错误提示。

**证据**

- 对话框清单；
- 自动回答依据；
- 歧义输入的阻断日志。

**通过条件**

- 正常病例没有重复的无意义弹窗；
- 歧义不会被默认答案吞掉；
- 标注者只在必须做决定时被打断。

### P10 保存、完成、复查和阻塞

**目的**
确认真实标注过程不被简化成“打开后一次完成全部器官”。

**操作**

1. 编辑后只保存进度，确认没有创建已验证标签。
2. 准备两个目标组：一个确认完成，一个含不确定器官。
3. 分别提交完成和提交复查。
4. 制造质量检查失败。
5. 制造工具或数据错误并报告阻塞。

**证据**

- `.mcs` 检查点；
- 提交清单；
- 每个目标组的状态变化；
- 质量检查和错误报告。

**通过条件**

- 保存不等于提交；
- “需要复查”仍使用草稿标签，不新增标签生命周期状态；
- 只有完成提交并通过平台检查才创建已验证标签；
- 一个目标组的问题不撤销其他已完成组；
- 工具错误与医学不确定可以区分。

### P11 已验证标签的再次修订

**目的**
确认已验证标签仍可继续改，但不能覆盖旧版本。

**操作**

1. 以一个已验证标签创建新的修订任务。
2. 检查本地工作区的基础标签哈希。
3. 修改并重新提交。
4. 查询旧快照引用的标签版本。

**证据**

- 旧标签标识和哈希；
- 新标签标识；
- `parent_label_id`；
- 旧快照引用记录。

**通过条件**

- 修订创建新版本；
- 旧版本保留；
- 已有快照不随修订改变；
- 基础版本不一致时拒绝提交并要求重新同步。

### P12 多标注者

**目的**
确认不同标注者可以并行处理不同病例或目标组。

**操作**

1. 把不同任务或目标组分给不同标注者。
2. 故意重复分配同一目标组。
3. 在基础版本更新后提交旧任务。
4. 设置负责人后，由其他人尝试提交。

**证据**

- 分配清单；
- 提交者标识；
- 基础版本哈希；
- 拒绝原因。

**通过条件**

- 正常情况下不同病例可以并行；
- 重复分配、过期基础版本和越权提交可以被发现；
- 阶段 A 不要求实现在线锁或实时租约。

### P13 异常反馈

**目的**
确认标注者能判断是继续修正、重新同步还是报告管理员。

至少制造以下问题：

- Mask 绑定错误 image set；
- 数组哈希或 shape 错误；
- 未知 Mask 名称；
- 空间变换无法解释；
- Mimics 脚本异常退出。

每份报告至少包含：

- 问题代码；
- 病例和任务标识；
- 发生阶段；
- 预期值与实际值；
- 日志位置；
- 推荐动作。

**通过条件**

- 错误不会静默通过；
- 标注者看到的是可操作说明，不是 Python 堆栈；
- 管理员可以从日志定位技术原因。

### P14 端到端闭环

**目的**
确认 Mimics 不是孤立工具，而是能完成平台的一次真实流转。

```text
数据导入
  -> 去标识检查
  -> 患者、检查和序列分组
  -> 图像登记
  -> 可选候选标签生成
  -> 创建标注任务
  -> Mimics 编辑、保存和提交
  -> 导出 Mask
  -> 外部格式转换和质量检查
  -> 创建已验证标签版本
  -> 创建训练数据快照
  -> nnUNet 适配器试导出
```

**证据**

- 图像、标签、任务和提交记录；
- 工具与脚本版本；
- 完整来源链；
- 质量检查报告；
- 训练试导出结果。

**通过条件**

- 草稿、待复查和检查失败结果不会进入已验证路径；
- 标签训练编号来自任务标签映射，不来自 Mimics 内部编号；
- 可以从最终标签追溯到输入病例、标注任务和工具版本。

### P15 Project Tree 任务清单对象

**目的**
验证是否可以在 Mimics Project Tree 中创建一个非阻塞、可持久保存的任务清单对象，用来显示目标器官列表。

**操作**

1. 在 Mimics Python Console 中枚举 `mimics.data` 可用对象集合，确认是否存在适合承载项目级备注的对象类型。
2. 尝试创建不会遮挡图像视图的候选对象，例如项目备注、Custom 对象，或带 metadata 的轻量测量/点对象。
3. 将对象命名为 `SP Review Summary`，写入当前 review、image set 和目标器官清单。
4. 保存 `.mcs`，关闭后重新打开，检查该对象是否仍在 Project Tree 中可见。
5. 运行提交脚本，确认该对象不会被误识别为受管 Mask、不会影响导出，也不会要求额外许可模块。

**证据**

- 可用对象类型截图或 API 枚举输出；
- 创建对象的脚本片段；
- 保存重开后的 Project Tree 截图；
- 提交脚本日志。

**通过条件**

- 标注者可以在左侧 Project Tree 或等价位置看到任务清单；
- 清单不遮挡图像，不要求标注者确认，不参与导出；
- 保存重开后仍存在；
- 不需要额外不可控模块许可。

若任一条件不满足，生产流程继续使用 `Labeling_View_Task_List.py`，不依赖 Project Tree 注释。

## 4. 执行顺序

1. 编写最小 `doctor`、`sp_diagnostics.py` 和 P01/P02/P04/P05/P06 探针。
2. 确认 edition、license、脚本入口和环境。
3. 完成 P01 至 P03，固定图像输入边界。
4. 完成 P04 和 P05，证明单个 Mask 缓冲区及空间坐标能够无歧义往返。
5. 完成 P06，证明可按任务选择性导出 Mask。
6. 达到 Gate A 后，再实现生产用打开、提交和收尾脚本。
7. 完成 P07 至 P09，验证恢复能力和操作成本。
8. 完成 P10 至 P13，验证实际工作流。
9. 使用全部样例执行 P14，并据此判断是否达到 Gate B 或 Gate C。
10. P15 是易用性增强，不阻塞 Gate B；通过后再把任务清单同步到 Project Tree。

P05 未通过前，不扩展批量处理和生产自动化。探针输出必须保留为版本特定证据。

## 5. 最终决策

| 结果 | 决策 |
|---|---|
| P01 至 P14 全部通过 | 可作为主要标注工具 |
| P15 通过 | 可增加 Project Tree 常驻任务清单；不通过则保留 Task List |
| 人工编辑可用，但导入、导出或批量不稳定 | 只用于疑难病例，主流程采用其他工具 |
| P05 不通过 | 不进入平台主路径 |
| P10 至 P13 不通过 | 工具本身可用，但平台工作流尚未成立 |
| license 或脚本权限不足 | 降级为手动辅助工具或更换工具 |

## 6. 交付物

- 一份环境和 license 记录；
- 3 至 5 个测试病例包；
- 人工体模及空间变换结果；
- P01 至 P15 的逐项证据；
- 实际使用的探针脚本及其版本；
- 导入、导出、空间检查和异常日志；
- 保存、复查、修订和多人任务记录；
- 通过、部分通过或不通过的结论；
- 至少一个替代标注工具的最小验证结果。
