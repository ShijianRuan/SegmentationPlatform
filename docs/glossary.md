# 分割平台常用词说明

> 日期：2026-06-13
> 用途：解释设计文档中的固定用词。第一次阅读平台文档时，不需要背诵这些词；遇到不清楚的名称再回来查即可。

## 1. 先看一条完整关系

一位标注者看到的是“病例、标注任务和提交结果”。平台内部会把同一件事拆成几份可追溯的记录：

```text
病例（Case）
-> 图像记录（Image Artifact）
-> 标注任务（Review Task）
-> 标签记录（Label Artifact）
-> 训练数据快照（Dataset Snapshot）
-> 模型记录（Model Record）
-> 评估记录（Evaluation Record）
```

这样拆分不是为了增加概念，而是为了回答几个实际问题：

- 这份标签对应哪张图像？
- 标签由谁或哪个算法产生？
- 训练时实际用了哪个标签版本？
- 标签后来被修正后，旧模型还能否复现？
- 模型在哪个独立数据集上评估过？

## 2. 数据和记录

| 文档用词 | 容易理解的说法 | 它实际表示什么 |
| --- | --- | --- |
| Case | 病例工作单元 | 一次标注、训练或评估所需的病例上下文。一个 Case 可以包含同一次检查中的多个序列。 |
| Image Artifact | 图像记录 | 一个独立三维体素网格，可以来自 DICOM 序列、NIfTI、MHD+RAW 或带读取参数的 RAW，并记录文件组、空间证据和用途限制。 |
| Label Artifact | 标签记录 | 一份多标签文件或一组逐器官 mask，以及每个器官标签的来源、状态和版本。 |
| Artifact | 已登记的数据项 | 对图像、标签等可追踪文件的统称。文档单独讨论图像或标签时，优先使用中文具体名称。 |
| Data Registry | 资产登记册 | 平台用来查找病例、图像、标签、模型和运行记录的目录。第一阶段可以是一组 JSON/YAML 文件，不一定是数据库。 |
| manifest | 清单文件 | 描述一批文件及其关系的 JSON/YAML 文件。它记录“有哪些文件、分别是什么”，不保存图像像素本身。 |
| schema | 清单格式规则 | 规定清单文件有哪些字段、字段类型是什么。`schema_version` 用于区分不同版本的格式。 |
| hash | 文件校验值 | 根据文件内容计算的标识。文件内容只要变化，校验值通常也会变化，可用于发现覆盖或传输损坏。 |
| immutable | 创建后不再修改 | 例如训练数据快照创建后不改写。需要使用新标签或新规则时，创建新快照。 |

## 3. 标签和训练

| 文档用词 | 容易理解的说法 | 它实际表示什么 |
| --- | --- | --- |
| Anatomy Vocabulary | 器官名称表 | 统一不同数据集和工具对同一器官的叫法，例如把 `left_kidney` 映射为平台名称 `kidney_left`。 |
| TaskLabelMap | 任务标签编号表 | 规定某个训练任务中各器官使用哪个整数编号。不同任务可以使用不同编号。 |
| Combine Map | 合并输出编号表 | 把多个局部模型的结果放进一份全身 mask 时使用的编号和覆盖顺序。它不参与模型训练。 |
| lifecycle status | 标签生命周期状态 | 说明标签当前属于外部来源、模型候选、人工草稿、人工确认或拒绝中的哪一种。 |
| label policy | 标签准入规则 | 创建训练数据快照时，用来判断哪些标签可以进入本次训练的规则。 |
| admission decision | 本次训练的准入结果 | 某份标签按照本次快照规则得到的“采用或不采用”结论。它只属于这次快照，不会改写标签来源。 |
| Dataset Snapshot | 训练数据快照 | 一次训练实际使用的数据清单。它固定病例、标签版本、训练/验证/测试划分和准入规则。 |
| TaskDefinition | 训练任务模板 | 后续可选的复用配置，提供任务标签映射和默认准入策略；一次训练仍以快照中冻结的完整策略为准。 |
| FewShotProtocol | 少样本实验清单 | 记录一次少样本实验实际使用的 support 病例、K 值、重复编号和随机种子。它是研究配置文件，不是平台核心实体。 |
| missing label | 图像覆盖了器官但没有标注 | 这种情况不能自动当作背景，否则模型会把真实器官学成背景。 |
| uncovered | 图像没有覆盖该器官 | 该病例不能为这个器官提供正样本或负样本监督。 |
| confirmed absent | 已确认器官不存在 | 只有图像确实覆盖了相应区域，且人工或可靠规则确认器官不存在时，才可作为负样本。 |

## 4. 来源、质量和安全

| 文档用词 | 容易理解的说法 | 它实际表示什么 |
| --- | --- | --- |
| provenance | 来源链 | 记录数据来自哪个数据集、标注者、模型或算法，以及经过哪些修订。 |
| lineage | 血统关系 | 特别用于模型和伪标签，说明一个结果是否由某个上游模型或标签间接产生。 |
| geometry | 图像空间信息 | 包括体素数量、体素间距、原点、方向和坐标变换。它决定 mask 是否与图像真正对齐。 |
| affine | 体素坐标到物理坐标的变换矩阵 | 仅仅 shape 相同并不能证明图像和标签对齐，还要检查 affine 或等价空间信息。 |
| QC | 质量检查 | Quality Control 的缩写。平台用自动检查发现文件损坏、空间错位、空标签、异常标签值和规则不满足。 |
| gate | 阻断检查 | 某项检查不通过时，不允许继续导出、训练或发布。正文优先直接写“阻断检查”。 |
| leakage group | 防数据泄漏分组 | 将同一患者或不能跨训练集与测试集的相关病例放在同一组。 |
| usage constraints | 使用限制 | 数据或模型能否用于训练、商业用途、再分发和发布衍生模型等约束。 |

## 5. 工具和运行

| 文档用词 | 容易理解的说法 | 它实际表示什么 |
| --- | --- | --- |
| Adapter | 工具适配器 | 把平台的标准输入转换为 Mimics、nnUNet 或外部算法需要的格式，并把结果转换回平台记录。 |
| materialize / materialization | 生成实际目录或文件 | 例如把训练数据快照导出成 nnUNet 的 `imagesTr`、`labelsTr` 和 `dataset.json`。正文优先写“导出”。 |
| Review Task | 标注或复查任务 | 说明谁要在哪些图像上处理哪些器官，以及任务当前是进行中、待复查还是完成。 |
| target group | 一组一起提交的标注目标 | 同组器官一起提交完成或一起进入复查；不同组可以独立完成。 |
| Candidate Generation Job | 候选标签生成批次 | 一次批量推理运行的记录，包含输入、模型或算法、参数、逐病例结果和失败重试。 |
| Model Record | 模型记录 | 一次训练产出的模型版本及其训练数据、配置、权重、限制和运行状态。 |
| Evaluation Record | 评估记录 | 模型在某个独立评估集上的一次不可修改的评估结果。 |
| label_generation | 候选标签生成域 | 负责运行模型或外部算法、登记候选标签、执行质量检查并把结果送往人工复查或训练选择。 |
| POC | 可行性验证 | Proof of Concept 的缩写。用于验证关键能力是否真实可行，不代表已经形成生产功能。 |
| Orchestrator | 流程调度器 | 后续用于串联多个平台动作的服务。第一阶段可以由命令行脚本完成同样的顺序。 |
| Workflow Action | 用户动作 | 例如“创建标注任务”“创建训练快照”和“启动候选标签生成”。第一阶段不需要把它建成独立数据库对象。 |
| support set | 少量已标注示例 | 在少样本实验中用于训练、微调、构造器官表示或作为推理上下文的病例集合。 |
| query set | 当前任务中的待预测样本 | 元学习或上下文分割中，由模型根据 support 进行预测或计算损失的样本；正式独立测试集仍需单独保留。 |

## 6. 文档写作约定

后续文档遵循以下规则：

1. 第一次出现固定英文名称时，先写中文含义，再在括号中写英文规范名。
2. 同一段后续优先使用中文简称，例如“数据登记册”“训练数据快照”“工具适配器”。
3. 字段名、目录名、命令和代码中的英文保持不变，避免实现时产生歧义。
4. 缩写第一次出现时必须展开，例如“质量检查（Quality Control，QC）”。
5. “阻断检查”“导出实际文件”“来源链”等中文能够准确表达时，不单独使用 `gate`、`materialize`、`provenance`。
