# 上下文学习与持续学习研究摘要

> 状态说明：这是面向平台架构讨论整理的摘要版，不是原始研究文档；若与 `docs/architecture/platform_blueprint.md` 冲突，以平台蓝图为准。  
> 原始来源：https://uih.feishu.cn/docx/LsV0dXqIjoJs7KxnWONcyqhunjh  
> 本轮处理：删除未逐条核实的论文摘录、榜单链接、参数规模和指标描述，只保留与平台设计有关的边界判断。

## 1. 为什么保留这份文档

上下文学习、foundation model、视觉语言模型和持续学习都可能影响后期分割平台：它们可以作为草稿标签生成器、交互式标注助手、病例筛选器或模型更新策略。

但当前平台的中心不是“大模型能力”，而是一个可追溯的分割数据流程：

1. 病例进入平台。
2. 标签来源被记录。
3. 人工或策略审核标签。
4. 生成训练快照。
5. nnUNet Adapter 先跑通。
6. 离线批量推理产生下一轮候选标签。

大模型相关能力只能接在这个流程上，不能替代这个流程。

## 2. 这些方向在平台中的合理位置

| 方向 | 合理角色 | 不应承担的角色 |
| --- | --- | --- |
| 上下文学习分割 | 生成 `candidate_label` 或辅助交互 | 直接定义平台真值 |
| 视觉语言模型 | 帮助查询、解释或选择病例 | 自动决定训练标签是否合格 |
| foundation model | 作为外部 Tool Adapter | 取代 Dataset Snapshot 和 label policy |
| 持续学习 | 后期模型改进实验 | 第一阶段主流程 |
| 主动学习 | 后期选择高价值审核病例 | 代替人工或质量规则 |

一句话：这些方法可以提高效率，但平台仍要保存“标签从哪里来、谁接受、进了哪个任务、训练了哪个模型”。

## 3. 为什么第一阶段不采用

| 原因 | 说明 |
| --- | --- |
| 评估难 | 没有冻结评估集时，很难判断大模型或持续学习是否真的提升 |
| 数据重 | 3D 医学影像上下文和显存成本高，不能默认适合平台批处理 |
| 标签边界不稳定 | 大模型输出可能需要人工修正，不能直接当训练标签 |
| 合规和许可复杂 | 外部模型、外部数据和模型权重许可需要单独检查 |
| 工程负担大 | 服务化、缓存、交互、回滚和日志都会增加复杂度 |

因此主蓝图选择把这些能力放在 Tool Adapter 或 Model Improvement 层，而不是放进第一阶段核心流程。

## 4. 后期接入方式

推荐把 foundation model 或上下文学习模型当成一种外部标签来源：

```text
case image
        ↓
external model adapter
        ↓
candidate_label
        ↓
quality check / human review
        ↓
accepted_pseudo_label or verified_label
        ↓
task Dataset Snapshot
        ↓
training
```

这样即使以后换模型，平台也不需要重写标签治理和训练快照逻辑。

## 5. 持续学习的最低要求

持续学习只有在下面条件满足后才值得做：

1. 有固定的病例注册表。
2. 有冻结的验证/测试病例。
3. 有模型版本记录。
4. 每个训练快照都可复现。
5. 能区分人工标签、外部来源标签和伪标签。
6. 能回滚模型。
7. 能比较新旧模型在相同评估集上的表现。

如果这些条件不满足，持续学习会让平台看起来“自动进化”，但实际上难以审计。

## 6. 对当前架构的启发

当前阶段只需要预留三个接口：

| 接口 | 作用 |
| --- | --- |
| `candidate_label` | 接收外部模型或上下文学习模型输出 |
| `label_policy` | 判断候选标签是否可以成为训练准入标签 |
| `Model Registry` | 记录模型来源、训练快照和评估结果 |

这三个接口比直接引入某个大模型更重要。它们能保证平台以后有能力接新模型，而不是被某个模型绑死。

## 7. 后续文献核查清单

如果恢复原始研究条目，需要逐项确认：

| 核查项 | 要求 |
| --- | --- |
| 论文是否存在 | 标题、作者、年份、arXiv/DOI/会议必须对应 |
| 是否医学相关 | 不能把自然图像结论直接搬到 CT/MR 分割 |
| 是否 3D 可用 | 2D 分割、2.5D、3D 的工程代价不同 |
| 是否需要交互 | prompt、示例、人工点选等输入要写清 |
| 输出是否可训练 | 输出是 mask、概率图还是文本描述 |
| 许可和权重 | 模型权重、代码和数据许可要分开检查 |

在这些核查完成前，本文件不引用具体论文结论作为平台设计依据。
