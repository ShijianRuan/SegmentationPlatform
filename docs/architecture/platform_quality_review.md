# 分割平台多角色设计审查

> 日期：2026-06-13
> 用途：记录本轮架构审查发现的问题、取舍和整改结果
> 说明：本文件是审查记录，不定义平台最终行为。当前设计见[平台蓝图](platform_blueprint.md)。

## 1. 审查依据

审查从项目最终目标反推：

> 任意来源的医学影像能够安全进入平台，经过人工标注或修订后形成可复现训练数据；模型完成训练和独立评估后，可以生成有明确来源的候选标签并回流。单人阶段可以用离线脚本完成，后续服务化不改变核心数据规则。

审查重点：

1. 异常、中断、多人协作和候选标签回流时，规则是否仍然成立。
2. 文档是否与当前目录和代码一致。
3. 第一阶段是否只实现必要能力，没有提前建设复杂服务。

## 2. 使用了哪些视角

| 视角 | 主要检查 |
| --- | --- |
| 平台负责人 | 目标、三大实现域和阶段范围 |
| 医学数据治理 | 患者关联、去标识、来源、许可和影响追溯 |
| 标注运营 | 中断、不确定、多序列、多人和返修 |
| 训练开发 | 训练数据快照、缺失标签、数据划分和框架接入 |
| 评估 | 独立评估、指标和失败病例追溯 |
| 候选标签生成 | 批量运行、部分失败、重试和回流 |
| 后端开发 | 标识、重复运行、追加版本和文件到数据库迁移 |
| 交付 | 计划、任务清单、现有实现和验收是否一致 |
| 文档维护 | 阅读入口、重复内容和术语解释 |
| 反向风险审查 | 静默错位、数据泄漏、自我确认和错误传播 |

## 3. 总体结论

三大实现域和主要数据关系是合理的，不需要推倒重来。原设计主要缺少四条完整链路：

1. 医学数据从受控原始区进入工作区的去标识检查。
2. 标注任务按目标组部分完成，避免一个不确定目标阻塞整例。
3. 正式评估独立记录，以及模型何时允许生成正式候选标签。
4. 候选标签批次的重复运行、部分失败和重试。

这些问题可以先用清单文件和少量状态解决，不需要数据库、消息队列或审批系统。

## 4. 已修正的问题

### 4.1 去标识边界

问题：患者标识的普通哈希不能证明原始 DICOM、文件名和日志已经去除直接身份信息。

整改：

- 区分受控原始区和工作区。
- 工作区只接收去标识状态已确认的数据。
- 病例包、训练导出和日志不得包含直接患者标识。
- 稳定患者关联使用受保护映射或带密钥的伪名化过程。
- 第一阶段仍由脚本和清单实现，不建设身份权限服务。

### 4.2 整例一次提交过于僵硬

问题：多序列、多器官任务中，一个无法确认的器官会阻塞其他已完成结果。

整改：

- 标注任务仍表示一份病例工作。
- 目标组成为最小提交单位。
- 一个组内一起完成或一起复查。
- 不同组可以分别完成、复查或阻塞。

### 4.3 正式评估不能覆盖写入模型记录

问题：同一模型会在多个评估集和代码版本上重复评估，覆盖写会混淆训练验证指标与正式指标。

整改：

- 模型记录保存训练事实和训练验证指标。
- 每次正式评估创建独立、不可修改的评估记录。
- 正式评估记录保存评估数据、代码、泄漏检查、指标和失败病例。
- 模型要经过显式检查，才能用于正式候选标签生成。

### 4.4 候选标签批次缺少失败恢复

问题：只有“输入和输出”说明，不能处理一个病例失败、重跑覆盖或任务中断。

整改：

- 每次批量运行创建候选标签生成批次。
- 保存生成器、输入、参数、标签映射和重复运行标识。
- 每个病例独立记录成功、失败或跳过。
- 成功结果不覆盖，失败病例可以单独重试。

### 4.5 对现有 nnUNet 代码描述过于乐观

代码检查发现：

- 缺少 `meta.csv` 时随机划分，且没有患者级保证。
- `dataset.json` 的部分来源和许可写死。
- 缺失器官 mask 会保留为背景 0。
- Surface Dice 依赖没有启用。

整改：继续复用训练核心，但在 nnUNet 工具适配器和独立评估流程中补齐这些规则。

### 4.6 计划编号过多

原文档中总体计划、近期任务和 Mimics 验证都使用相似编号，容易误读。

当前约定：

| 范围 | 编号 |
| --- | --- |
| 总体实施里程碑 | `M0` 至 `M9` |
| 第一次闭环检查点 | `B0` 至 `B6` |
| Mimics 验证项 | `P01` 至 `P14` |
| 架构成熟阶段 | A 至 E |

## 5. 不能为了简单而删除的规则

以下规则直接防止错误数据进入训练：

- 图像和标签的空间信息与文件校验值。
- 标签来源和五种生命周期状态。
- 未覆盖、缺少标注和确认不存在的区分。
- 训练数据快照创建后不修改。
- 患者泄漏和模型伪标签来源泄漏检查。
- 数据和模型使用限制沿来源传播。

## 6. 第一阶段明确延后的能力

- Web 界面和任务队列。
- 在线领取、超时回收和完整权限系统。
- 多人盲审和复杂仲裁。
- 任务模板继承。
- 基于概率图的模型输出冲突仲裁。
- 复杂解剖层级知识库。
- 通用少样本工具适配器。
- 模型签名和发布服务。
